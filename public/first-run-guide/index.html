Install & first-run setup

The setup wizard detects your hardware, tunes sensible defaults, seeds starter slots, and (optionally) pulls starter models.

install
hal0 --version
one time
preflight
hal0 doctor
GPU · ports · disk
wizard
hal0 setup
tune defaults
verify
hal0 status
API on :8080
bash
$ hal0 --version              # → hal0 0.9.2
$ hal0 doctor                 # re-run installer preflight checks
$ hal0 setup                  # interactive first-run wizard

# prefer hands-off? recommended defaults, no prompts:
$ hal0 setup --auto              # full auto, downloads starter models
$ hal0 setup --auto --no-pull    # seed slots only, pull models later

$ hal0 status                 # confirm the daemon is alive
💡 Fast path: hal0 setup --auto gives you a working system in one step. The stages below are what setup does under the hood — do them manually when you want to add your own models and slots.
1

Add your first models

Pull a curated model by its alias. Downloads run as a background job on the daemon with a live progress bar.

bash
$ hal0 model pull qwen3-4b        # download from Hugging Face
$ hal0 model list                 # what you have + what you can pull
$ hal0 model show qwen3-4b        # inspect metadata

# already have weights on disk? register instead of downloading:
$ hal0 model register /mnt/ai-models/MyModel/model.gguf
Done when — hal0 model list shows your model in the local registry.
2

Create & assign profiles

A profile is the “how to run it” recipe — container image, engine flags, backend (vulkan/rocm/cpu), and whether MTP speculative decoding is on. Profiles are shared: any slot can name the same one.

profile · saber-fpx
image  = …:rocmfpx
backend = vulkan
flags  = -fa on -ngl 999 …
mtp    = true
named by
slot · utility
"profile" : "vkfpx-moe"
"model"   : "qwen-…-35b"
"port"    : 8081
bash
# 1) list existing profiles — a seed one often already fits
$ curl -s http://127.0.0.1:8080/api/profiles | jq '.[].name'

# 2) create a custom profile by editing config, then reload
$ hal0 config edit            # add a [profile.my-profile] block
$ hal0 config validate        # check before applying
$ hal0 config reload          # daemon re-reads the TOMLs
Copy an existing block like [profile.saber-fpx] and tweak flags/backend rather than writing one from scratch. A slot references a profile by name via its "profile" field.
Done when — your profile appears in /api/profiles and hal0 config validate passes.
3

Create your first slot

A slot is a named worker bound to a port, a type, a backend, and a model. Creating it writes config; it stays offline until you load it.

bash
$ hal0 slot create primary \
    --type llm \
    --model qwen3-4b \
    --hardware vulkan \
    --ctx-size 8192

# other slot types work the same way
$ hal0 slot create embed --type embedding -m qwen3-embedding-0-6b-q8-0
$ hal0 slot create stt   --type transcription -m whisper-v3:turbo
FlagMeaningDefault
--typellm · embedding · reranking · transcription · tts · imagellm
--model / -mModel ref to assign (required)—
--hardwarevulkan · rocm · cpuauto-detected
--port / -pTCP portauto, 8081–8099
--ctx-sizeContext window4096
bash — re-point a slot later
$ hal0 model assign qwen3-4b --slot primary   # set default, no reload
$ hal0 slot edit primary --ctx-size 16384       # tweak config fields
Done when — hal0 slot list shows your slot (reads offline until loaded).
4

Bring slots online

Loading starts the engine and occupies the port. Here’s the slot lifecycle:

offline
slot load
loading
ready
serving ✓
slot unload
offline
bash
$ hal0 slot load primary            # start the engine
$ hal0 slot list                   # state: offline → serving
$ hal0 slot status primary          # includes config-drift warnings
$ hal0 slot logs -f primary         # follow startup logs live

# everyday controls
$ hal0 slot swap primary -m qwen3-8b  # change model, survives restart
$ hal0 slot restart primary         # unload then load
$ hal0 slot unload primary          # free the GPU / port
⚠️ Single-GPU boxes (Strix Halo): the iGPU is time-shared across slots — loading several heavy slots at once contends for memory bandwidth. Load what you need; unload what you don’t.
Done when — hal0 slot list shows serving and logs report the model loaded.
5

Wire a capability — optional but recommended

Slots are plumbing; capabilities are the roles apps actually ask for. Mapping agent → your slot means requests to the hal0/agent role route there — no app needs to know the port.

role · agent slot · primary
role · voice.tts slot · tts

Roles live in /etc/hal0/capabilities.toml — agent, utility, embed, rerank, voice.tts, img, vision. Assign via the dashboard picker, or repair/validate selections on the CLI:

bash
$ hal0 capabilities migrate --dry-run   # preview changes
$ hal0 capabilities migrate             # snap selections to legal slots
